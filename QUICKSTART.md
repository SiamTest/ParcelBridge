# Push ParcelBridge and build your Android app

1. Extract this ZIP. Upload the **contents of the `ParcelBridge` folder** to `SiamTest/ParcelBridge` on the `main` branch. Include the hidden `.github` folder, `.gitignore` and `.gitattributes`.
2. Open the repository's **Actions** tab. **Test and build** runs automatically. API deployment runs inside **Test and build** when configured. After that entire workflow passes on `main`, **Android release** starts as a separate Action and publishes a GitHub release for Android-source changes (not for workflow-only/API-only edits), then optionally uploads a Play draft. Missing deployment credentials skip deployment; missing signing secrets switch the APK release to a test prerelease and skip Play upload. Pull requests run checks only.
3. Create a Turso **libSQL** database and a GitHub environment named `production`. Add `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` as repository or production-environment secrets. Your existing repository secrets work; you do not need to duplicate them.
4. Review Feni coverage and prices in `api/wrangler.jsonc`. API deployment runs automatically when its credentials exist; **Deploy Cloudflare API** can also be run manually.
5. Deploy the private backend plus public gateway using **Deploy Cloudflare API**. Run `python3 scripts/make-pairing-code.py` locally and provide the gateway origin. In the app, choose **Pair device**, paste the generated code, and sign in. Do not configure `API_BASE_URL`; Android builds do not embed URLs.
6. Register a seller and a rider. Promote your trusted operator account using the SQL in `README.md`; approve the rider from Operator tools.
7. Android signing secrets are optional. Run **Test and build** on `main` or push a commit to publish an installable test APK as a GitHub prerelease without them. To enable production-signed APKs and Play AABs, create and back up a persistent keystore and add all four `ANDROID_*` secrets listed in `README.md`. **Android release** appears as a separate workflow run after checks/deployment succeed, checks out the tested commit and assigns an increasing version code and publishes the APK and manifest; it includes the Play AAB only for production-signed builds. You can still push a tag such as `v1.0.0` or run the release workflow manually. Test builds remain prereleases even with a plain version tag.
8. For Google Play, create the Play app and configure its signing, listing and service-account access. Add `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`; each configured signed release then uploads an internal-track draft automatically. Review and publish through Play Console. Use `PLAY_TRACK` to choose another track, or `AUTO_UPLOAD_PLAY=false` to keep draft uploads manual.
9. To clean completed Actions runs immediately, open **Actions → Clean completed Actions runs → Run workflow**, choose the default branch and leave **mode = all_completed**. This deletes completed runs, logs and artifacts, including old workflows; download anything needed first. It keeps active runs, its current run and GitHub Releases. Automatic cleanup runs after completion and every ten minutes: successes are deleted immediately, while failures/cancellations are retained for 20 minutes. GitHub scheduled sweeps can be delayed. No cleanup variables are required; optional minute-based overrides are `CLEANUP_SUCCESS_MINUTES` and `CLEANUP_FAILURE_MINUTES`. The current cleanup itself remains until another run cleans it.

Test prerelease APKs use runner-generated debug keys: they cannot update production installations, and installing a later test build may require reinstalling. Add production signing secrets for stable updates and Google Play. APK and Play variants have separate package IDs and update channels. The direct APK build supports automatic update checks and optional verified Wi-Fi downloads; Android asks for installation approval.

No passwords or account credentials are included in this archive. Never commit your Turso token, Cloudflare token, Play service-account JSON or signing keystore.

This is a pilot. Test actual deliveries and two consecutive signed updates on real phones before launch. Prices and the approximate three-kilometre Feni zone are configurable. COD records are bookkeeping; this app does not transfer money.

See `README.md` for all features, setup details and remaining launch work.
